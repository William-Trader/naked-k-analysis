# 运行观察与优化日志 · 2026-10-27

## 一、现象（QQ 成交量告警）

- 每天每个币 5–7 条 `volume_spike`，连续多日。
- 告警文案出现「成交量突然放大（约 34.6 倍平时）」，其中 ETH 单日最大 `vol_z=53.0`。
- 告警状态：`sent 76 / stale 62`，说明推送量与积压都偏高。

## 二、根因（三处叠加）

1. **单位错误**：`vol_z` 是 z-score（标准差倍数），文案却写成「倍平时」，
   于是 34.6σ 被展示成「34.6 倍成交量」。
2. **1m 量能口径过松**：monitor 用 20 根 1m 的**原始均值/标准差**算 z；
   夜间成交量平稳时 sd 接近 0，z 会爆到几十。阈值又只有 3。
3. **P2 也在推送**：`push_pending` 只按静默时段过滤，未按级别过滤，
   于是本该只进 4h 简报的 P2 也发到 QQ。

## 三、修复

- 量能改为**稳健口径**：`log(volume)` + median/MAD（`nakedk.features.volume_z`）。
- 新增**真实倍数** `vol_ratio = 当前量 / 近 20 根中位量`。
- 触发条件改为**双条件**：`vol_z ≥ 5` 且 `vol_ratio ≥ 3`。
  - `vol_ratio ≥ 5` → P1（推送）；
  - `3 ≤ vol_ratio < 5` → P2（只入库，不推送）。
- 文案改用 `vol_ratio`：「约 X 倍平时」；缺失时不再编数字。
- P2 告警标记 `p2_deferred`，不进入 QQ 推送队列。
- `volume_spike` 冷却单独设为 240 分钟；`replay.py` 同步使用稳健口径。

## 四、多交易所加权（免费源）

- 新增 `nakedk/sources.py`：Binance / Gate / Bybit / OKX，按 24h 成交额加权。
- 服务器实测可达：**Binance 200、Gate 200**；OKX、Bybit 超时 → 持久封禁 30 分钟，
  避免每次分析都等超时（fetch 从 17.1s 降到 11.1s）。
- 输出 `MULTI|...|weighted=...|dev=...%`；偏差 >0.5% 时额外输出 `DATA_WARN`。

实测：

```
MULTI|BTC|n=2|weighted=79738.85|median=79740.14|dev=0.005%|binance:79740.14,gate:79736.2
POLICY|BTC|regime=range|dir=short|action=allow|basis=0.121
```

## 五、准确性检查

- 多源价差 **0.005%**（5bp 以内），主源可信。
- 量能指标回到正常区间：`BTC z=-0.27 ratio=0.83`、`ETH z=-1.17 ratio=0.46`、
  `SOL z=0.02 ratio=1.01`。
- 分析链仍完整输出：`POLICY / REGIME / PATTERN_MTF / PROB / PLAN`。
- 测试：**145 个全过**。

## 六、仍存在的边界

- OKX / Bybit 在该服务器不可达，当前加权只有两源；等网络或代理恢复后会自动纳入。
- `PROB` 在 `down` 桶仍为 `insufficient`（n=75 < 100），按设计不给百分比。
- fetch 仍有约 11s（analogs + 多周期 + 逐笔），后续可加同 bar 缓存。
